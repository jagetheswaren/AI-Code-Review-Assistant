# ML Architecture

## Overview

The ML severity classification system predicts the severity of code analysis findings discovered by the static analysis pipeline. It operates as an optional enrichment layer — if the model fails or is not loaded, the system falls back to rule-based severity from the static analyzers.

## Pipeline

```text
Source Code
    ↓
Static Analyzers (Bandit, AST, Radon, Performance)
    ↓  produce List[Issue] with rule-based severity
FindingAggregator.merge_findings()
    ↓  deduplicated, sorted List[Issue]
NLP Explainer (CodeGPT fallback)
    ↓  adds explanation / fix_suggestion per issue
ML SeverityClassifier.predict()
    ↓  attaches ml_severity, ml_confidence, ml_model_version
ReviewResponse → API → Frontend
```

## Classifier

| Property | Value |
|----------|-------|
| Algorithm | `RandomForestClassifier` |
| Hyperparameters | `n_estimators=100, max_depth=10, min_samples_split=5, min_samples_leaf=2` |
| Class weighting | `class_weight='balanced'` |
| Random seed | `42` |
| Preprocessing | `StandardScaler` on features, `LabelEncoder` on labels |
| Labels | `info`, `low`, `medium`, `high`, `critical` (5 classes) |

## Feature Set

### v2-no-leakage (current, v3 model)

10 features extracted per issue. **No feature encodes the target label.**

| # | Feature | Description | Range |
|---|---------|-------------|-------|
| 1 | `issue_type_encoded` | security=0, performance=1, code_smell=2, best_practice=3 | {0,1,2,3} |
| 2 | `has_suggestion` | 1 if suggestion field is present | {0,1} |
| 3 | `has_code_snippet` | 1 if code_snippet field is present | {0,1} |
| 4 | `message_length` | `len(message) / 500`, capped at 1.0 | [0, 1] |
| 5 | `rule_id_length` | `len(rule_id) / 50`, capped at 1.0 | [0, 1] |
| 6 | `is_security_related` | 1 if issue type is security | {0,1} |
| 7 | `is_complexity_related` | 1 if issue type is performance | {0,1} |
| 8 | `has_explanation` | 1 if explanation field is present | {0,1} |
| 9 | `line_number_normalized` | `line_number / 1000`, capped at 1.0 | [0, 1] |
| 10 | `has_fix_suggestion` | 1 if fix_suggestion field is present | {0,1} |

### v1-legacy (v1/v2 models, deprecated)

The original feature set included `rule_severity_encoded` at index 1, which was a direct numeric encoding of the severity label (the prediction target). This constituted **target leakage** — the model was effectively memorizing the answer.

Legacy feature extraction is preserved in `_extract_features_v1()` for backward compatibility when loading v1/v2 models.

## Dataset

> **⚠️ Limitation**: There is no real dataset of labeled code review findings. The model is trained on **purely synthetic data** generated by `generate_synthetic_training_data()`.

| Property | Value |
|----------|-------|
| Type | Synthetic (generated at training time) |
| Size | 2000 samples |
| Seed | `np.random.seed(42)` |
| Label source | `np.random.choice(severities, p=severity_weights)` conditioned on issue type |
| Real code | None — issues contain random template messages, not actual code analysis output |

### Class Distribution (n=2000)

| Class | Count | Percentage |
|-------|-------|------------|
| low | 603 | 30.1% |
| medium | 499 | 24.9% |
| high | 369 | 18.4% |
| info | 295 | 14.8% |
| critical | 234 | 11.7% |

Imbalance ratio (max/min): **2.58**. Handled via `class_weight='balanced'`.

## Model Versioning

Models are saved as joblib bundles in `backend/ml/models/` containing:

```python
{
    'model': <sklearn classifier>,
    'scaler': <StandardScaler>,
    'label_encoder': <LabelEncoder>,
    'is_trained': bool,
    'feature_names': List[str],
    'model_version': str,       # e.g., 'v3'
    'model_name': str,          # e.g., 'RandomForestClassifier'
    'feature_version': str,     # e.g., 'v2-no-leakage'
    'training_date': str,       # ISO 8601
    'supported_classes': List[str],
    'training_config': dict,    # hyperparameters
}
```

| Version | Feature Set | Status |
|---------|-------------|--------|
| v1 | v1-legacy (with leakage) | Fallback |
| v2 | v1-legacy (with leakage) | Fallback |
| v3 | v2-no-leakage | **Current** |

The loader tries v3 → v2 → v1 → fallback locations.

## Confidence

The `ml_confidence` value is `max(predict_proba(...))` — the highest class probability from the Random Forest ensemble. This is an **uncalibrated probability estimate**, not a calibrated confidence score. Values closer to 1.0 indicate stronger agreement among the trees.

## Inference Integration

In `review_routes.py`:

1. `SeverityClassifier` is instantiated and loaded at module import time (line 32-33).
2. Per issue, the Pydantic `Issue` object is converted to a plain dict (line 95-104).
3. `predict([dict])` is called, which extracts features, scales, and predicts.
4. The result writes `ml_severity`, `ml_confidence`, `ml_model_version` back onto the Issue.
5. If the model is not trained, fallback returns the original rule-based severity with confidence 0.5.

## Limitations

1. **Synthetic data only** — The model has never been trained on real code review findings.
2. **Limited signal** — Without the leaked severity feature, the remaining features (issue type, boolean flags, normalized lengths) carry minimal predictive power for severity classification.
3. **No real-world evaluation** — All reported metrics are on synthetic test data.
4. **Feature redundancy** — `is_security_related` and `is_complexity_related` are derivable from `issue_type_encoded`.

## Future Work

- Compile a dataset of real human-reviewed code findings with severity labels.
- Add code-derived features (cyclomatic complexity score, nesting depth, number of affected lines).
- Evaluate on real data before replacing the production model.
- Consider probability calibration (Platt scaling or isotonic regression).
