# Machine Learning Pipeline Architecture

IntelliReview AI utilizes a Machine Learning subsystem specifically for **severity and risk prediction**. The goal of the ML layer is to take raw, factual findings generated by the static analysis tools (Bandit, Astroid, Radon) and dynamically predict their contextual severity and confidence score.

## Separation of Concerns
1. **Static Analysis**: Generates factual findings (line numbers, rules violated).
2. **Machine Learning Model**: Predicts contextual severity (critical, high, medium, low, info).
3. **LLM (Ollama/Groq)**: Generates human-readable explanations, context, and actionable fix suggestions.

## Model Details

* **Algorithm**: Random Forest Classifier (`sklearn.ensemble.RandomForestClassifier`)
* **Framework**: Scikit-Learn
* **Current Version**: `v3`
* **Features Version**: `v2-no-leakage`

## Features Extracted
The model currently uses the following features from the static analysis output:
- `issue_type_encoded`: Encoded category (`security=0`, `performance=1`, `code_smell=2`, `best_practice=3`)
- `has_suggestion`: Boolean presence of a static fix suggestion
- `has_code_snippet`: Boolean presence of a parsed code snippet
- `message_length`: Normalized length of the violation message
- `rule_id_length`: Normalized length of the rule ID string
- `is_security_related`: Boolean
- `is_complexity_related`: Boolean
- `has_explanation`: Boolean presence of an LLM explanation
- `line_number_normalized`: Line number normalized against typical file lengths
- `has_fix_suggestion`: Boolean presence of a fix

### Target Leakage Fix (v2)
In version 1 of the model, the `rule_severity_encoded` feature was directly fed into the model. This was identified as **Target Leakage**, artificially inflating model accuracy to 99%. Version 2 removes this feature entirely to ensure the model actually learns contextual patterns rather than memorizing static severities.

## Training Data & Limitations

**SYNTHETIC DATASET WARNING**
The current model is trained on a **synthetic dataset** generated by `generate_synthetic_training_data()`. The severities are assigned using weighted random distributions based on issue types, rather than historically labeled human code reviews.

Because the data is synthetic, the model's predictions currently simulate ML behavior rather than providing production-grade, generalized insights. 

**Limitations:**
- The model will not generalize to real-world, nuanced code review severities.
- It is currently meant as a placeholder architecture to prove out the inference pipeline and API design.

## Reproducibility

To train a new version of the model, run the classifier script directly:

```bash
cd backend
python -m ml.severity_classifier
```

This will:
1. Generate a new synthetic dataset of 2000 samples.
2. Extract the `v2` features.
3. Train the Random Forest.
4. Export the weights to `backend/models/severity_classifier_v3.joblib`.

## Future Work
To make this model production-ready, the synthetic generator must be replaced with a pipeline that scrapes historical GitHub Pull Requests, extracting static analysis findings as features, and human review comments / subsequent commits as ground-truth severity labels.
